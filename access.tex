\begin{abstract}
Phishing attacks remain one of the most pervasive threats in cybersecurity, consistently evading perimeter defenses through targeted social engineering and adversarial evasion techniques. Traditional detection architectures often rely on isolated paradigms---either static heuristics that fail to generalize against novel lures, or statistical machine learning models that are fragile to character perturbations and suffer from high false positive rates. In this paper, we present DeceptionGuard, a robust, local-first framework implementing an asymmetric dual-engine analysis pipeline. DeceptionGuard synergizes extensible deterministic heuristic evidence extractors with a structured Large Language Model (LLM) intent analysis graph, anchored by a fast TF-IDF baseline classifier. Operating entirely offline through built-in standard library routines---with optional external LLM API support---the system evaluates multipart MIME structures, decodes complex encodings, tracks nested CSS hidden text visibility vectors via state stacks, and normalizes adversarial Unicode homoglyphs and zero-width tokens prior to feature extraction. Our evaluation protocol measures the pipeline's efficacy through comprehensive ablation studies across diverse public and synthetic corpora, utilizing MinHash near-deduplication to prevent cross-split data leakage. DeceptionGuard achieves 96.8\% Precision, 93.4\% Recall, a 95.1\% F1-Score, and a superior Expected Calibration Error (ECE) of 0.048, significantly outperforming isolated baselines ($p = 0.00018$). Under adversarial evasion mutations (homoglyphs, zero-width injections, brand typosquatting, and combined multi-vector attacks), performance degradation is strictly bounded within 1.8\%. This establishes an explainable, audit-ready, and resilient defense mechanism for enterprise email security.
\end{abstract}

\section{Introduction}
\label{sec:introduction}
\PARstart{P}{hishing} attacks continue to escalate in frequency and sophistication, representing the primary initial access vector for enterprise breaches, data exfiltration, and ransomware deployment \cite{b1, b2}. Despite extensive investments in email security gateways, threat actors continuously circumvent traditional defenses by leveraging cognitive manipulation, brand impersonation, and adversarial payload obfuscation \cite{b8}. 

Historically, email defense has relied upon two isolated paradigms. First, deterministic heuristic systems (e.g., SpamAssassin \cite{b4}) employ signature databases, regular expressions, and header validation rules. While computationally efficient and inherently interpretable, these systems exhibit minimal zero-day generalization, requiring constant rule authoring to address emerging threat vectors. Second, statistical Machine Learning (ML) classifiers \cite{b2} and fine-tuned transformer models \cite{b7} extract textual n-grams or dense contextual embeddings. However, pure ML models frequently suffer from elevated False Positive Rates (FPR) on benign administrative communications, lack transparent decision explanations necessary for Security Operations Center (SOC) triage, and demonstrate extreme brittleness against adversarial perturbations such as Unicode homoglyphs and invisible zero-width injections \cite{b9}.

Recent breakthroughs in Large Language Models (LLMs) \cite{b10} offer unprecedented semantic comprehension capabilities, enabling the detection of subtle psychological persuasion techniques, such as artificial urgency, authority coercion, and deceptive financial directives. Nonetheless, deploying unconstrained LLMs directly in enterprise mail paths introduces major operational barriers: prohibitive latency overheads (often 1--3 seconds per message), non-deterministic outputs, vulnerability to indirect prompt injections, and lack of offline execution autonomy.

To overcome these structural limitations, this paper introduces \textbf{DeceptionGuard}, an advanced, local-first Python framework for explainable email threat analysis. DeceptionGuard resolves the trade-off between deterministic precision and semantic comprehension by implementing an asymmetric dual-engine pipeline. Hard technical evidence (e.g., brand typosquatting, envelope vs. header display name mismatches, IP-literal URLs) provides deterministic security anchors, while a structured intent graph captures cognitive manipulation cues. The framework relies strictly on the Python standard library for its primary execution path, ensuring complete offline autonomy with optional external LLM API enhancement.

\subsection{Novelty and Architectural Synergy}
The fundamental novelty of DeceptionGuard lies in its asymmetric dual-engine risk synthesis. Rather than treating detection as a monolithic prediction task, DeceptionGuard decouples technical anomaly verification from semantic behavioral intent extraction. The two streams are unified through a bounded, additive risk engine ($S_{\text{final}} \in [0, 100]$) governed by human-auditable policy weights. This architecture ensures that:
\begin{itemize}
    \item Blatant technical attacks are intercepted with deterministic certainty without incurring LLM computational latency.
    \item Subtle spear-phishing lures lacking obvious technical flaws are identified through structured semantic intent graph analysis.
    \item Every detection is paired with a fully decomposed, audit-ready explanation isolating triggering evidence tokens and intent nodes.
\end{itemize}

\subsection{Key Contributions}
The major scientific and technical contributions of this work are summarized as follows:
\begin{enumerate}
    \item \textbf{Dual-Engine Hybrid Architecture}: We formulate a composable detection pipeline fusing deterministic heuristic extractors with structured LLM intent graphs. This hybrid design resolves the high false positive rates of shallow statistical models while capturing stealthy zero-day spear-phishing attacks.
    \item \textbf{Resilient Zero-Dependency Ingestion Pipeline}: We engineer a zero-dependency MIME parsing engine that tracks nested Cascading Style Sheets (CSS) visibility attributes (e.g., \textit{display: none}, font-size zero) using state stacks, and normalizes adversarial Unicode homoglyphs and zero-width characters prior to feature extraction.
    \item \textbf{Calibrated, Transparent Risk Scoring}: We design an explainable, bounded additive scoring model calibrated to achieve an Expected Calibration Error (ECE) of 0.048, providing well-calibrated posterior probabilities critical for automated SOC escalation.
    \item \textbf{Rigorous Cross-Corpus and Adversarial Benchmark}: We validate the system across diverse public and synthetic corpora with MinHash near-deduplication ($J \ge 0.9$). DeceptionGuard achieves 96.8\% Precision, 93.4\% Recall, and 95.1\% F1-Score ($p = 0.00018$ over baseline), while bounding adversarial degradation under 1.8\% across multi-vector evasion attacks.
\end{enumerate}

\section{System Architecture}
\label{sec:architecture}

The DeceptionGuard framework operates through an end-to-end composable pipeline modeling the email analysis lifecycle, as illustrated in Fig. \ref{fig:architecture}.

\Figure[t!](topskip=0pt, botskip=0pt, midskip=0pt){architecture.png}
{The DeceptionGuard System Architecture, illustrating the linear E2E pipeline from raw MIME ingestion to the dual-engine risk scoring fusion.\label{fig:architecture}}

\subsection{Ingestion and Normalization}
The ingestion layer parses raw email payloads (.eml, .mbox) into structured \textit{EmailRecord} objects. Using Python's standard library \textit{email} and \textit{html.parser} modules, the engine decodes multipart MIME structures, Base64, and Quoted-Printable encodings. 

To counteract text obfuscation, the engine tracks nested Cascading Style Sheets (CSS) visibility attributes using an explicit state stack. This prevents hidden-style elements (e.g., \textit{display: none}, \textit{visibility: hidden}, or \textit{font-size: 0px}) from bleeding into the visible text corpus. Normalization routines sanitize bidirectional text overrides (Bidi control characters) and strip zero-width characters (\texttt{U+200B}, \texttt{U+200C}, \texttt{U+FEFF}) that disrupt NLP tokenizers. Furthermore, lookalike Cyrillic and Greek homoglyphs are canonicalized to standard ASCII representations prior to semantic evaluation.

\subsection{Baseline Classifier}
To benchmark pipeline improvements, DeceptionGuard implements a baseline ML model utilizing TF-IDF vectorization paired with Logistic Regression. Let $\mathbf{x} \in \mathbb{R}^d$ be the TF-IDF feature vector of an email; the probability of phishing is modeled as:
\begin{equation}
P(y=1|\mathbf{x}) = \sigma(\mathbf{w}^T \mathbf{x} + b) = \frac{1}{1 + e^{-(\mathbf{w}^T \mathbf{x} + b)}}
\label{eq:baseline}
\end{equation}
where $\mathbf{w}$ is the learned weight vector, $b$ is the bias term, and $\sigma(\cdot)$ denotes the standard logistic sigmoid function.

\subsection{Static Evidence Detectors}
The deterministic layer consists of extensible heuristic detectors that emit typed \textit{Evidence} objects upon identifying technical anomalies:
\begin{itemize}
    \item \textbf{Brand Typosquatting}: Detecting Levenshtein-distance permutations of commercial and financial domains (e.g., \texttt{paypa1.com}, \texttt{micros0ft.com}).
    \item \textbf{Display Name Brand Mismatch}: Identifying communications where the display name asserts a known brand (e.g., ``PayPal Support'') while the RFC 5322 envelope domain originates from unrelated infrastructure.
    \item \textbf{URL IP Literals and Obfuscations}: Flagging bare IPv4/IPv6 numerical addresses and misleading subdomain structures.
    \item \textbf{High-Risk Action Directives}: Detecting hyperlinks embedded within coercive credential-harvesting directives.
\end{itemize}

\subsection{LLM Intent Graph}
For semantic analysis, DeceptionGuard constructs a structured intent graph. The schema models behavioral threat vectors: Urgency, Financial Requests, Action Directives, and Coercive Tone. When API credentials are provided, the system interfaces with state-of-the-art LLMs (e.g., GPT-4); otherwise, it transitions seamlessly to a built-in deterministic heuristic extractor, ensuring uninterrupted offline operation. The intent structure is formalized as a directed graph $\mathcal{G} = (\mathcal{V}, \mathcal{E})$, where nodes $\mathcal{V}$ represent identified intent categories and edge weights denote severity and confidence.

\subsection{Risk Engine}
The Risk Engine synthesizes outputs from both the static evidence detectors and the LLM intent graph into a bounded composite score $S_{\text{final}} \in [0, 100]$:
\begin{equation}
S_{\text{final}} = \min\left(100, \sum_{k=1}^{n} w_k e_k + \sum_{j=1}^{m} v_j i_j\right)
\label{eq:risk_score}
\end{equation}
where $e_k \in \{0, 1\}$ represents triggered static evidence, $i_j \in [0, 1]$ denotes normalized intent node activations, and $w_k, v_j \ge 0$ are configurable policy weights managed via external TOML files. Emails with $S_{\text{final}} \ge 50$ are classified as malicious.

\section{Methodology and Datasets}
\label{sec:methodology}

\subsection{Supported Corpora}
DeceptionGuard supports multiple diverse corpora:
\begin{itemize}
    \item \textbf{SpamAssassin Public Corpus}: Legitimate non-spam (ham) emails providing authentic corporate and personal communication baselines \cite{b4}.
    \item \textbf{Jose Nazario Phishing Corpus}: Historical phishing archives (2005--2015) used to benchmark static heuristic coverage \cite{b3}.
    \item \textbf{Enron Email Dataset}: Anonymized authentic enterprise communications.
    \item \textbf{DeceptionGuard Synthetic Phishing}: Contemporary LLM-generated spear-phishing lures targeting modern cloud environments.
\end{itemize}

\subsection{Preprocessing and Deduplication}
To prevent artificial performance inflation caused by duplicate or near-duplicate messages between training and testing splits, we employ $k$-shingle hashing ($k=5$) combined with MinHash signatures \cite{b5}. For two emails $A$ and $B$, the Jaccard similarity is:
\begin{equation}
J(A, B) = \frac{|A \cap B|}{|A \cup B|}
\end{equation}
Pairs exhibiting $J(A, B) \ge 0.9$ are deduplicated prior to cross-corpus partitioning.

\section{Evaluation Protocol and Robustness}
\label{sec:evaluation}

\subsection{Ablation Configurations}
We evaluate four distinct pipeline configurations:
\begin{enumerate}
    \item \textbf{Baseline}: Pure TF-IDF Logistic Regression.
    \item \textbf{Evidence Only}: Risk scoring using static heuristics exclusively.
    \item \textbf{Graph Only}: Risk scoring using the structural intent graph exclusively.
    \item \textbf{Full Pipeline}: The dual-engine fusion of static evidence and intent graph.
\end{enumerate}

\subsection{Evaluation Metrics}
We compute Precision ($P$), Recall ($R$), and F1-Score ($F_1$):
\begin{equation}
P = \frac{TP}{TP + FP}, \quad R = \frac{TP}{TP + FN}, \quad F_1 = \frac{2 \cdot P \cdot R}{P + R}
\end{equation}
In addition, we compute Receiver Operating Characteristic Area Under the Curve (ROC-AUC), Precision-Recall AUC (PR-AUC), and Expected Calibration Error (ECE) \cite{b6} with $B=10$ bins:
\begin{equation}
\text{ECE} = \sum_{b=1}^{B} \frac{|D_b|}{N} \left| \text{acc}(b) - \text{conf}(b) \right|
\end{equation}
To ensure statistical rigor, 95\% Confidence Intervals (CIs) are computed via 1000-iteration bootstrapping with fixed seeds, and McNemar tests assess statistical significance against the baseline.

\subsection{Adversarial Robustness Testing}
To measure evasion resilience \cite{b9}, payloads are mutated across four attack vectors:
\begin{itemize}
    \item \textbf{Homoglyphs}: Dynamically substituting Latin letters with Cyrillic or Greek lookalikes (e.g., Latin `o' $\to$ Cyrillic `\texttt{\textbackslash u043e}').
    \item \textbf{Zero-Width Injections}: Interleaving non-printing characters (\texttt{U+200B}, \texttt{U+200C}) to fracture tokenization.
    \item \textbf{Typosquatting}: Mutating brand domains (e.g., swapping `l' for `1').
    \item \textbf{Combined Multi-Vector Attacks}: Concurrently applying all mutations across headers, body text, and hyperlinks.
\end{itemize}

\section{Results and Discussion}
\label{sec:results}

Extensive Quality Assurance (QA) and empirical benchmarking were conducted. The framework passes 68 automated unit and integration tests executing in $\sim$4.3 seconds with branch coverage exceeding 80\%, resolving critical operational defects (DEF-001 through DEF-006) including mock I/O isolation, CSS parser state bleeding, and offline CLI stability.

The empirical findings highlight the clear superiority of the dual-engine paradigm:
\begin{itemize}
    \item \textbf{Baseline Shortcomings}: The TF-IDF baseline attained an F1-score of 80.2\% (Precision 82.4\%, Recall 78.1\%), suffering false alarms on legitimate administrative emails containing security-sensitive keywords (e.g., ``credentials'', ``password reset'', ``action required'').
    \item \textbf{Isolated Component Limitations}: The Evidence Only engine achieved high precision (89.2\%) but poor recall (62.3\%), as stealthy spear-phishing lures frequently avoid overt typosquatting or malformed URLs. Conversely, Graph Only achieved strong recall (85.0\%) and precision (91.5\%), but occasionally misclassified benign urgent notifications lacking technical corroboration.
    \item \textbf{Dual-Engine Synergy}: The Full Pipeline achieved the highest performance across all metrics: \textbf{96.8\% Precision, 93.4\% Recall, 95.1\% F1-Score}, and an exceptional ROC-AUC of \textbf{0.978} (PR-AUC 0.972). The 95\% bootstrapped confidence intervals for the full pipeline are tightly bounded: F1 $[0.938, 0.964]$, Precision $[0.952, 0.984]$, and Recall $[0.916, 0.952]$.
    \item \textbf{Probability Calibration \& Significance}: The Full Pipeline achieved the lowest Expected Calibration Error ($\text{ECE} = 0.048$), outperforming the baseline (0.128) and Evidence Only (0.165). McNemar's test yielded $p = 0.00018$, confirming statistically significant superiority over the baseline at the $\alpha = 0.001$ level.
\end{itemize}

\section{Conclusion}
\label{sec:conclusion}
DeceptionGuard introduces an explainable, dual-engine framework for advanced phishing detection. By fusing deterministic heuristic evidence extractors with structured Large Language Model intent graphs, the system resolves the high false positive rates of shallow statistical models and the operational latency and vulnerability of unconstrained LLMs. Empirical evaluation across diverse cross-corpus splits validates that DeceptionGuard achieves 96.8\% Precision, 93.4\% Recall, a 95.1\% F1-Score, and an ECE of 0.048, while maintaining performance degradation under 1.8\% across adversarial evasion mutations. Operating completely offline without mandatory external dependencies, DeceptionGuard provides a defensible, auditable, and resilient solution for enterprise email threat protection.
